Act as an expert web designer, UX/UI designer, brand strategist, and full-stack developer. Build a complete, premium, production-quality adventure tourism website for Earth Adventure, an adventure company operating in Oman.

Reference website: https://casamasirah.com/

Use the reference to understand the range of tourism services, page structure, customer journey, and booking experience. Create an original design inspired by the same level of quality and completeness. Never copy the reference website's exact design, layout, branding, text, or components.

## 11. Functional On-Site Booking Request System

This is one of the most important parts of the website.

Build a polished, functional booking request form directly on the website. Customers must be able to submit a request without being forced to open WhatsApp.

### Booking form fields

Required fields:
- Selected experience.
- Customer full name.
- Contact number with country code.
- Preferred date.
- Number of participants.

Optional fields:
- Email address.
- Preferred language.
- Special requirements.
- Additional notes.

Include the following behavior:
- Automatically populate the selected experience when booking from an experience card or detail page.
- Allow customers to change the selected experience.
- Validate required fields.
- Validate that the participant count is a positive integer.
- Prevent past dates from being selected.
- Show clear inline validation errors.
- Display a loading state while submitting.
- Prevent accidental duplicate submissions.
- Display a success confirmation after a request is successfully saved.
- Display an understandable error message if submission fails.

### Booking request workflow

For the initial version, implement a genuine booking inquiry workflow.

Use Supabase as the preferred backend if supported by the Lovable project. Configure a booking_requests table with appropriate fields, including:
- Unique request ID.
- Experience ID.
- Customer name.
- Contact number.
- Email, if provided.
- Preferred date.
- Participant count.
- Additional notes.
- Submission timestamp.
- Request status.

Set the initial status to “pending.”

Implement appropriate Row Level Security and database permissions. Public visitors should be able to submit booking requests but must not be able to read other customers' private booking details.

Do not expose privileged API keys or service-role credentials in client-side code.

If Supabase credentials have not been configured, build the complete form interface and clearly explain which backend configuration is still required. Never simulate successful database storage.

Clearly distinguish between a submitted request and a confirmed booking.
